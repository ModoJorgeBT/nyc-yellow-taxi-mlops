## T26 — Workflow preparado

`.github/workflows/ci.yml` ejecuta Ruff, formato, dependencias, Pytest, HTTP
503 real sin champion y build/inspección de la imagen de producción. Usa
Ubuntu 24.04 y los entornos Docker fijados; no instala paquetes globalmente,
no descarga datasets ni usa modelos reales. Las pruebas ajustan únicamente
fixtures sintéticas pequeñas. La imagen CI agrega Ruff 0.17.3 fijado por hash;
el lock Linux de serving y los locks Windows se conservan.

`actions/checkout` v6 se verificó en el repositorio oficial y se fijó al SHA
`d23441a48e516b6c34aea4fa41551a30e30af803`. Token de solo lectura y credenciales
sin persistir; sin `pull_request_target`, publicación de imágenes ni merge.
La [guía de GitHub](https://docs.github.com/en/actions/reference/security/secure-use)
explica el pin por SHA. GitHub validará además la sintaxis al ejecutar el workflow.

Validación Linux local completa: **PASS, 601 pruebas**, Ruff sobre 100 archivos,
formato, dependencias y smoke HTTP 503 real, en 158,26 s de Pytest. Para evitar la latencia de
SQLite en un montaje Windows, se copia un checkout sin datos/Registry a
filesystem Linux de un contenedor efímero; se ejecuta como UID 10001 con los
mismos límites de CI. El runner GitHub usa su disco Linux nativo.

La prueba detectó tres diferencias de plataforma y se corrigieron: sin
ejecutable Git se registra revisión desconocida, conservando el hash del
código; un proceso Linux terminado sin VmHWM se trata como terminado, pero
un proceso activo sin medición sigue bloqueado; el smoke detiene el worker
HTTP separado de MLflow solo tras verificar su ascendencia e identidad con
pidfd. La comprobación de puerto ocupado permanece activa. Las 34 pruebas
enfocadas Linux, incluido registro/reinicio real con fixtures, pasaron.

El build CI exige límites efectivos cgroup de 2 CPU/4 GiB además del mínimo
de disco. Un builder Docker aislado limita el conjunto de etapas, además
de los límites por RUN; no se depende del BuildKit del runner. Se fijó
BuildKit v0.34.2 por digest, verificado con el Registry oficial. Los límites
globales CPU/memoria/swap y el probe desde RUN pasaron; builder de prueba
detenido, sin cambiar el predeterminado. [Opciones oficiales del driver](https://docs.docker.com/build/builders/drivers/docker-container/)
y [release fijada](https://github.com/moby/buildkit/releases/tag/v0.34.2).
El perfil por defecto del build local conserva 50 GiB.

La imagen de producción también construyó y pasó inspección efímera como
UID 10001, filesystem de solo lectura, sin raw ni .env. No sustituyó la API
activa. Evidencia local en `.cache/t26-t28/ci-full.log` y `.json`; los intentos
fallidos anteriores quedaron conservados, sin presentar sus resultados como PASS.
La carrera residual de recolección de zombies quedó cubierta por dos casos
deterministas: terminado se recoge; activo sin medición continúa bloqueado.

La aceptación remota exige PR verde y demostración roja/verde en rama aparte.
El usuario aprobó el paquete de publicación después de verificarlo localmente:
ramas y commits de T20–T28, PR en borrador y demostración separada; sin merge.
Publicación en ejecución, todavía sin atribuirle resultados remotos.

## T27 — Métricas del servicio

`src/api/metrics.py` observa mensajes ASGI y mide hasta el último cuerpo
enviado, sin sumar trabajos posteriores de background. Rutas acotadas,
conteos por código, 4xx/5xx, solicitudes interrumpidas y throughput por
segundo observado. Si no se observó ninguna cabecera HTTP se registra
`no_response`, sin inventar un código. p50/p95 usan interpolación lineal
exacta sobre respuestas completas; sin muestras son null. Con más de 10.000
solicitudes en la ventana, ambos quedan null y NOT_AVAILABLE_OVERFLOW; los
contadores siguen completos. Memoria de muestras acotada por proceso.

Ventanas UTC de 60 s avanzadas por reloj monotónico; primera/última pueden
ser parciales y su denominador refleja solo el tiempo observado. Se emiten
al siguiente evento que cruza de ventana o al cierre ordenado. Intervalos sin
eventos se identifican como huecos no observados. Un cierre abrupto puede
perder la ventana en memoria. No se calcula ni promete disponibilidad/SLA.

Logs `metrics_window` contienen agregados, sin cuerpo, headers, query, IP ni
identificadores de viajes. No se añadió ningún endpoint al contrato D-06.
Los percentiles de distintas ventanas no se promedian como si fueran un
percentil global. Cada worker/reinicio tiene boot_id para separar observaciones.

```powershell
docker compose logs --no-color api | Out-File -Encoding utf8 .cache/api-metrics.log
.\.venv\Scripts\python.exe -m src.api.metrics --log-file .cache/api-metrics.log --output reports/operational/export.json
```

El exportador deduplica boot_id/ventana y rechaza duplicados divergentes y
sobrescrituras; se necesita al menos una ventana emitida. Evidencia real
Docker en `reports/operational/t27/`: ventanas de serving con 200/422 y de
instancia aislada sin recibos con 503, percentiles y contadores comprobados.
La instancia de prueba se retiró; API v4 permanece saludable en 8080.

## T28 — Calidad y schema retrospectivos

`configs/monitoring-quality.yaml` fija 18 reportes por ruta/hash/raw SHA y
linaje al split T14. Se comprobó una identidad común de esquema/reglas D-04,
excluyendo solo metadatos administrativos de aprobación/procedencia. Cada
referencia usa un escaneo completo de 2024 sin FAIL y aceptado para calidad.
No se releen Parquet ni etiquetas para esta tarea: se reutiliza evidencia
histórica completa de T10. No acredita el estado actual de bytes raw sin
una nueva ingesta/validación.

`src/monitoring/data_quality.py` compara columnas/tipos/nullable, volumen y
tasas agregadas de reglas de nulos/categorías. No obtiene distribuciones por
categoría ni nulos por columna cuando el reporte no los contiene. Esos datos
no se inventan. Los cambios relativos son descriptivos; no hay umbrales nuevos.
Un reporte de rechazo estructural puede observarse sin simular estadísticas
de filas que no fueron escaneadas.

Los seis meses conservan ALERT_D04_FAIL por las reglas ya incumplidas y las
aceptaciones excepcionales exactas originales; el agregado de schema muestra
`cbd_congestion_fee` respecto a 2024. Esa columna opcional conocida no se
autoriza como feature. Monitorear no aprueba un dataset ni concede excepciones.
No cambia D-04 ni evalúa PSI, desempeño, triggers o promociones D-05.

```powershell
.\.venv\Scripts\python.exe -m src.monitoring.data_quality --build-reference --output reports/monitoring/quality/reference-2024-v1.json
```
